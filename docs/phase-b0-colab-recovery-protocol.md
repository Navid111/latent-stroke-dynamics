# Phase B0 Google Colab CUDA recovery protocol

## Purpose

Recover the frozen Phase B0 development study after the local Apple Silicon attempt was intentionally interrupted for thermal safety. The local attempt completed zero model variants, saved no checkpoint, performed no long-horizon evaluation, and produced no scientific decision. This recovery is therefore a replacement for an incomplete infrastructure attempt, not a rerun of a completed experiment.

## Evidence establishing recovery eligibility

- The interrupted local directory contains only four deterministic JSON manifests and remains preserved.
- The original authorization is consumed and cannot execute again.
- The Google Colab preflight passed 120 tests on a Tesla T4.
- All six raw resource hashes and all loaded model-state hashes matched.
- CPU/CUDA dummy outputs differed by at most `3.2782554626464844e-06`, below the frozen `5e-4` tolerance.
- Dummy gradients and losses were finite.
- The three-times training-only safety estimate was under 0.4 hours.

None of the dummy values are scientific evidence.

## Scientific invariants

The base Phase B0 architecture, objectives, variants, optimizer, batch sizes, epoch cap, patience, EMA, gradient clipping, development seeds, planner states, candidates, method order, long-horizon budgets, eligibility thresholds, and total six-hour cap remain unchanged.

The only permitted amendment is execution infrastructure:

- the new Phase B model, its diagnostics, and its planners execute in float32 on CUDA;
- the learned-pixel comparator may use CUDA through its existing device argument;
- PIL rendering, candidate generation, exact pixel planning, and the frozen archived MSE-only plus normalized-latent-L1 comparator remain on CPU;
- unused ranking-aware checkpoints must not be loaded.

## Environment freeze

The recovery environment must match the passing preflight: Tesla T4, compute capability 7.5, Python 3.13.15, PyTorch 2.11.0+cu128, CUDA 12.8, and cuDNN 91900. Automatic mixed precision and TF32 are disabled. cuDNN benchmark is disabled and deterministic mode is enabled.

Any mismatch stops before renderer-data generation.

## Data continuity

The renderer data remain defined by the original frozen seeds. Before training, the recovery runner must reproduce and hash the four manifests generated by the interrupted local attempt. Every hash must match the archived value. A mismatch stops before the first optimizer step.

The partial local artifacts are integrity references only and may not be copied into the recovery output or used for model selection.

## Persistence

The recovery output must live under a user-supplied Google Drive artifact root, never the ephemeral Colab repository. The runner creates a new `.incomplete` recovery directory, journals every completed stage, saves each completed variant and history immediately, preserves incomplete state on any error or interrupt, and atomically renames to the final directory only after the frozen decision and integrity manifest are written.

Automatic resume is not authorized. An interruption requires preserving the directory and a new audit.

## Lifecycle

Implementation and dummy-only validation occur while `recovery.authorized` is false. A passing implementation does not authorize data generation or training. Exactly one recovery execution may be authorized only by a later separate commit. Formal B0, B1, and B2 remain unauthorized.
